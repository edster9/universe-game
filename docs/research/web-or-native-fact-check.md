# Web or native: the claims checked

A fact-check, 2026-09-30, of the load-bearing claims in two reports from another AI that the owner brought (one on the web path, one on a thick client; summarised in "A thick client, not only the web" in [requirements.md](../requirements.md)). Sources are primary where marked. Used by [ideas/the-client.md](../ideas/the-client.md), alongside [webgpu-performance.md](webgpu-performance.md).

| # | Claim | Verdict | What the source says | Source |
| --- | --- | --- | --- | --- |
| 1 | WebAssembly memory is capped around 4 GB | Confirmed | V8 raised wasm32 memory from 2 GB to 4 GB in 2020, "the largest amount of memory possible with 32-bit pointers". On mobile, far less is usable in practice (forum reports of ~256–300 MB on Android Chrome; not primary). | [v8.dev](https://v8.dev/blog/4gb-wasm-memory) |
| 1b | 64-bit WebAssembly memory (Memory64) | Confirmed: Chrome/Edge 133+, Firefox 134+; **not Safari** (up to 27.1) | 73.8% global coverage. | [caniuse](https://caniuse.com/wf-wasm-memory64) |
| 1c | Memory64 costs speed | Confirmed | SpiderMonkey (Jan 2025): "10% to over 100%" slower, from bounds checks; the JavaScript API caps a memory at 16 GB. | [spidermonkey.dev](https://spidermonkey.dev/blog/2025/01/15/is-memory64-actually-worth-using.html) |
| 2 | WebGPU's default limits: 256 MiB buffers, 128 MiB storage bindings | Confirmed | More can be requested, up to what the adapter reports. | [MDN](https://developer.mozilla.org/en-US/docs/Web/API/GPUSupportedLimits) |
| 2b | Browsers put adapter limits in tiers (against fingerprinting) | Partly | Confirmed for Chrome (Dawn's tiers, up to 4 GB); opt-in in wgpu, unconfirmed for Firefox release builds; nothing found for Safari. | [Dawn](https://dawn.googlesource.com/dawn/+/716339fa9fe10b4383899bbe112479967b585d3c), [wgpu](https://wgpu.rs/doc/wgpu_core/limits/index.html) |
| 3 | The JavaScript heap is capped at 4 GB, in Electron too | Confirmed | Pointer compression from Electron 14, the V8 memory cage from Electron 21: "The V8 heap is limited to a maximum size of 4GB." | [Electron blog, June 2022](https://electronjs.org/blog/v8-memory-cage) |
| 4 | Electron's WebGPU is Chrome's | Partly | The same code (Dawn inside Chromium); no Electron document states identical limits, and flags and blocklists can differ. | [Dawn](https://dawn.googlesource.com/dawn) |
| 5 | Bevy's version | Update: **0.19.1** (Aug 2026) is the latest release; 0.20 at release candidate 2 (Sept 28) | | [bevy.org](https://bevy.org/news/), [releases](https://github.com/bevyengine/bevy/releases) |
| 5b | Bevy has ray-traced lighting (Solari) and DLSS natively | Confirmed | Both since 0.17 (Sept 2025); Solari is still "experimental… not yet usable for real games" in 0.19. Native only. | [0.17](https://bevy.org/news/bevy-0-17/), [0.19](https://bevy.org/news/bevy-0-19/) |
| 5c | Bevy on the web: WebGL2 by default, WebGPU by a feature | Confirmed | | [bevy.org](https://bevy.org/news/bevy-webgpu/) |
| 5d | Bevy web builds ~5–20 MB stripped | Unverifiable | Community reports only: ~15 MB default release, 40–50% smaller with size settings. | [discussion](https://github.com/bevyengine/bevy/discussions/2476) |
| 5e | Bevy breaks its API every release | Confirmed | The 0.18→0.19 guide covers deep changes; a 0.19→0.20 guide already exists. | [migration guide](https://bevy.org/learn/migration-guides/0-18-to-0-19/) |
| 6 | Browser audio adds 16–50 ms | Partly | The only real measurement (2021, macOS): ~55–67 ms by default, ~14–19 ms with the lowest latency setting. | [measurement](https://www.greaterwrong.com/posts/ooXEzrX7Y9Go6D7st/browser-audio-latency), [MDN](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/baseLatency) |
| 7 | WebGPU reaches 85–87% of users | Depends on the source | caniuse: 85.7% full, 88.8% with partial (Firefox and desktop Safari only partial); web3dsurvey, counting devices that actually get a working adapter: **82.2%**, and Linux 16.7%. | [caniuse data](https://github.com/Fyrd/caniuse/blob/main/features-json/webgpu.json), [web3dsurvey](https://web3dsurvey.com/webgpu) |
| 8 | three.js r186, Babylon.js 9.x, PlayCanvas 2.22 exist | Confirmed | r186 (Sept 24, 2026); Babylon.js 9.28.0 (Sept 24); PlayCanvas 2.22.6 (Sept 28). | [three.js](https://github.com/mrdoob/three.js/releases), [Babylon.js 9.0](https://blogs.windows.com/windowsdeveloper/2026/03/26/announcing-babylon-js-9-0), [PlayCanvas](https://github.com/playcanvas/engine/releases) |
| 9 | Fyrox on the web is OpenGL ES only; its wgpu backend a draft | Mostly, and outdated | WebGL2 on the web; a wgpu backend was merged Aug 17, 2026 as an optional "initial draft", unreleased, not on the web. | [Fyrox PR #927](https://github.com/FyroxEngine/Fyrox/pull/927) |
| 10 | Rust for Godot (gdext) is usable for games | Partly | "Usable state for projects such as games", with occasional breaking changes; web, Android, iOS experimental. v0.5.5 (Aug 2026). | [gdext](https://github.com/godot-rust/gdext) |
| 10b | Godot's web export has no WebGPU | Confirmed | Godot 4.7: web export targets WebGL 2.0 only. | [Godot docs](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html) |
| 11 | quinn (QUIC in Rust) is mature | Partly | Actively maintained since 2018, 30+ releases, still before 1.0. | [quinn](https://github.com/quinn-rs/quinn) |
| 11b | Big multiplayer games use UDP | Confirmed in substance | Unreal's standard net driver and Valve's GameNetworkingSockets run over UDP. | [GameNetworkingSockets](https://github.com/ValveSoftware/GameNetworkingSockets), [Unreal](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/OnlineSubsystemUtils/UIpNetDriver) |
| 12 | Browser storage is evictable and can't be memory-mapped | Confirmed | Shared per-site quota (Chrome up to 60% of disk; Firefox best-effort min(10%, 10 GiB)); evicted least-recently-used, whole site at once; Safari deletes script-written data after 7 days without interaction. No memory-mapping: data is copied into wasm memory. | [MDN quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria), [MDN sync access](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createSyncAccessHandle) |

**Strongest:** the memory ceilings (1), WebGPU's defaults (2), the 4 GB JavaScript heap, Electron included (3), the versions (8), and Godot's web export (10b). **Weakest:** the audio figure (6) and Bevy's web sizes (5d), both rough.
